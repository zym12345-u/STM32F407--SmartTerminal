| 项 | 初版复评 | 修订后 | 出处 |

## 一、总体结论

架构骨架清晰，分层（BSP / 移植层 / 任务层）到位，任务职责单一，中断内只做投递不做处理；看门狗 + DWT 运行时统计 + 复位来源诊断这套可观测性建设超出同类学习项目水平。**V1.1 未发现阻断性缺陷，不建议改动 main。**

## 二、分档结论

### A 档：真实缺陷

| # | 问题 | 出处 | 执行时机 |
|---|---|---|---|
| A1 | FreeRTOS 堆容量不足，V1.2 上 LittleFS+MQTT 后必撞墙 | `FreeRTOSConfig.h:72`=20480；9 任务栈 12320B；`esp8266-wifi-screen-debug` skill 记录 15KB 时 `osMessageQueueNew` 曾返回 NULL 致命令静默丢弃 | **V1.2 分支第一步**（main 不动）。先按 Keil map 做 RAM 预算再定扩容值（预期 32~40KB） |
| A2 | `Drivers/STM32F4xx_HAL_Driver/Src/` 无 `stm32f4xx_hal_spi.c`，而 V1.2 的 W25Q128 是 SPI 器件 | 该目录仅 16 个 .c（cortex/dma/dma_ex/exti/flash/flash_ex/flash_ramfunc/gpio/pwr/pwr_ex/rcc/rcc_ex/tim/tim_ex/uart/hal） | **V1.2 第一步**。方案已由驻场定案：补 HAL SPI + `stm32f4xx_hal_conf.h` 使能 `HAL_SPI_MODULE_ENABLED`，不走寄存器直配 |
| A3 | `.trae/skills/` 3 处与代码漂移 | 见下 | **已完成**（本次修正，属文档，不改代码） |

**A3 明细（已修正，2026-10-17）**

1. `esp8266-wifi-screen-debug/SKILL.md`：ESP8266 串口号原写 USART3(PB10/PB11) + 跳线第 2、3 行 → 实为 **USART2(PA2/PA3) 杜邦线**，USART3 已让给 RS485。板级事实写错，危害最大。
2. `stm32-freertos-task/SKILL.md`：`configTOTAL_HEAP_SIZE` 原写「必须提到 49152」→ 实际 **20480**，且与 esp8266 skill 的「已提到 20KB」自相矛盾。
3. `stm32-freertos-task/SKILL.md`：串口输出章节原写「不引入 printf 重定向」→ 实际已改为 `UART_Printf` + DMA2_S7 + 互斥锁 + `fputc` 重定向 + `__use_no_semihosting`，整节重写。

### B 档：风格偏好（建议不改，仅记录）

| # | 项 | 说明 |
|---|---|---|
| B1 | ESP8266 的 `USART2_IRQHandler` 定义在 `bsp_ESP8266.c` | 与 `usart.c` 的 `HAL_UART_MspInit`(USART2 分支)职责分散；改动会碰中断时序，收益不抵风险。建议仅加注释 |
| B2 | `bsp_LCD_ILI9341.c/.h` 中 HAL 风格（`GPIO_PIN_x`/`.Pin`）与标准外设库风格（`GPIO_Pin_x`/`GPIO_PinAFConfig`）混用、双套宏并存 | 移植期残留。已验证可用，不动 |
| B3 | LVGL 移植层位于 `LVGL/examples/porting/` | 升级 LVGL 会被覆盖；本工程不升级则无实际影响 |
| B4 | 共享数据保护策略不统一 | `g_sensorData` 无锁 / `g_clockData` 临界区 / `g_wifiScan` 事件同步。三者均有注释说明取舍，当前规模可接受 |

### D 档：观察项（不改代码，V1.2 时复查）

| # | 项 | 出处 / 触发条件 |
|---|---|---|
| D1 | `configUSE_TICKLESS_IDLE=1` 与 HAL 时基挂 TIM4 的组合 | `FreeRTOSConfig.h:67`、`stm32f4xx_hal_timebase_tim.c`。Sleep 期间 SysTick 停而 TIM4 继续，`uwTick` 唤醒后可能跳变，影响依赖 `HAL_GetTick` 的超时逻辑。V1.2 引入 MQTT 阻塞等待后风险放大 |
| D2 | IWDG 1s 窗口被长阻塞操作挤掉 | 驻场补充（已采纳）：W25Q128 块(64KB)擦除典型 400ms、最长 2s。较 MQTT 更可能先触发误复位 |
| D3 | `bsp_WifiStore.c` 的 `WifiStore_Save()` 已是「擦 sector11 + 按 word 写 + memcmp 回读」阻塞式全流程，且发生在任务上下文 | 巡检补充（待驻场确认）：V1.2 换 W25Q128+LittleFS 后擦写窗口更长，建议把「长擦写 + 喂狗豁免 / 拆片等待」做成**统一机制**，而非每个存储调用点各写一遍 |

## 三、执行清单

### 现在动 main 的项：**0 条**

按驻场 2026-10-17 裁决，A1/A2 的执行点均在 V1.2 分支。V1.1 保持已验证状态。

### V1.2 开工清单（第一步）

1. **RAM 预算 + 堆扩容** —— 以 Keil map 的 `ZI-data` 为准；硬约束：主 SRAM 112KB+16KB，**64KB CCM 无 DMA，DMA 缓冲不可放 CCM**
2. **补 HAL SPI** —— 加 `stm32f4xx_hal_spi.c` + 使能 `HAL_SPI_MODULE_ENABLED`
3. **W25Q128 驱动 + 喂狗豁免机制**（对应 D2/D3）
4. **LittleFS / MQTT 选型与预算**
5. 参考资源：网盘 `5、标准例程--HAL库版本/20-1 数据存储_W25Q128_SPI_外部FLASH`（现成例程）；`21-3 SD卡_SDIO_FatFs文件系统`（LittleFS 对照）

2. WiFi 配网 + 对时
