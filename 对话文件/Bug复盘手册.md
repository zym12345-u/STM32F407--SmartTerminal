## B-001 看门狗误复位（三层根因）

**现象**：配网保存后重启，boot 打印 `reset cause: IWDG watchdog!`

**根因链**（三次迭代才修对，每层都是独立根因）：

| 层 | 根因 | 修法 | 版本 |
|---|---|---|---|
| 1 | 擦除 128KB 内部扇区期间**全任务冻结** 1~2s，超过 1s 窗口 | `IWDG_SetReload(RELOAD_FLASH_SAVE=500)`，保存前后配对放宽/恢复 | V1.1.1 |
| 2 | `WiFi_JoinAp()` 里 `ESP8266_Cmd(CWJAP, "OK", 20000U)` **20s 阻塞等待**不回主循环，心跳停发 >3s | 等待循环内每 ~500ms 补心跳 | V1.1.2 |
| 3 | **快响应**路径：模块秒回（<500ms）时"节流心跳"整次调用一次都不触发；SNTP 轮询每轮 1.1s 零心跳 | `ESP8266_Cmd` **入口无条件报一次**，循环内节流保留 | V1.1.3 |

**为什么反直觉**：直觉是"等得久才饿死狗"。实际**快响应路径更危险**——节流逻辑在快路径上退化成零心跳。V1.1.2 恰恰死在"秒回"这个看起来最安全的场景。

**教训**：
1. 审计单位是**心跳空窗**，不是 CPU 忙闲。任何 >3s 不回到任务主循环的调用都是嫌疑犯
2. **最好时序与最坏时序都要算**：空窗 = 无心跳代码段的最长连续时长
3. 心跳注入的正确模式：**每次调用入口必报一次** + **长等待循环内节流补报**
4. **"复测通过"前不得宣布根因**（本条三次宣布三次翻车）

**出处**：`驻场通报_V1.1.1/V1.1.2/V1.1.3_2026-10-18.md`；日志 `records-2026-10-18-17-55 / 18-05 / 19-54`；commit `18d62cf`

## B-002 FreeRTOS 堆余量三数打架

**现象**：V1.2 要加 MQTT + LittleFS，堆够不够，三个数字互不吻合。

| 来源 | 数值 | 问题 |
|---|---|---|
| 巡检估算（任务栈累加法） | 5~6 KB | 纯推算，漏算队列/信号量/互斥锁等内核对象（合计约 1.8KB） |
| 驻场引用 `free heap after create` | 13968 B | **中途快照**——打印点在 `WifiTask_Create()`，其后 Modbus(2048)/Monitor(1024)/Stats(1024) 未建，Idle(512)/TmrSvc(1024) 更在 `osKernelStart()` 之后 |
| **真机实测** | **6352 B**（再扣 1536 → 稳态 ≈ 4.8 KB） | 定档值 |

**教训**：
1. **打印点决定数字含义**，引用日志数值前先确认它是哪一刻的
2. 估算只用来定方向，**定档必须实测**
3. 结论方向不变（V1.2 不够），但紧迫性由估算校准为实测后才准确

**处置**：A1 定档 `configTOTAL_HEAP_SIZE` 20KB → **32KB**，V1.2 第一步执行。

**出处**：`驻场实测回报_2026-10-17.md`；`freertos.c` 诊断打印；`FreeRTOSConfig.h:72`

## B-003 `0x080E0000` / Sector 11 地址疑点

**现象**：两个事实互斥，尚未定论。

- ✅ 硬件直读 `*(uint16_t*)0x1FFF7A22` = **512 KB**（两次 boot 一致）→ VET6 坐实，物理上只有 sector 0~7
- ❓ 但 V1.1.3 日志显示**开机自动连接成功**，而自动连接的前提是 `WifiStore_Load()` 从 `0x080E0000` 读到有效 magic

**假设与反例**：地址回绕别名（`0x080E0000 & 0x7FFFF = 0x08060000` → sector 7）。**反例**：若真如此，擦"扇区 11"会擦掉 sector 7，而程序止于 `0x0807A0A8` 正落在 sector 7 内，板子应早已变砖——它没有。故假设亦未证实。

**为什么值得记**：HAL 对 `STM32F407xx` 一律定义 `FLASH_SECTOR_TOTAL = 12U`（`stm32f4xx_hal_flash_ex.h:771-773`），`IS_FLASH_SECTOR(11)` 为真，**传不存在的扇区号不会报错，静默失败**。这类"库替你做了错误假设"的坑在 STM32 上不止一处。

**待做实验**（一行打印）：
```c
UART_Printf("[SYS] magic@0x080E0000=0x%08lX  word@0x08060000=0x%08lX  flashsz=%uKB\r\n",
            *(uint32_t*)0x080E0000U, *(uint32_t*)0x08060000U, *(uint16_t*)0x1FFF7A22U);
```
| 结果 | 结论 |
|---|---|
| E0000 有 magic 且 ≠ 60000 | 该地址独立可写，容量口径需再查 |
| E0000 == 60000 | **证实回绕别名** → 擦扇区可能毁代码，立即停用并迁移载体 |
| E0000 无 magic | 原"越界失效"结论成立，"自动连接"需另找来源 |

**处置**：出结果前**冻结对 `WifiStore` 的任何改动**。

**出处**：`驻场通报_2026-10-18.md`；`巡检回信_V1.1.3验收与地址别名疑点_2026-10-18.md`

## B-004 UV4 `-o` 相对路径静默失败

**现象**：命令行 `UV4 -j0 -b proj.uvprojx -o build_log.txt` 在 **IDE 打开工程时**会静默写失败，读到的是**旧日志**。驻场因此两次把 10-11 的旧日志当成"本次 0E0W"。

**教训**：**`已编译` 这个结论本身也需要证据**。今后必须：
1. `-o` 用**绝对路径**
2. 核对 **axf 时间戳新鲜度**

二者缺一不算"编译通过"。

**出处**：`驻场通报_D3坐实与V1.1.1_2026-10-18.md` 第四节

## 巡检错误台账（我的判断失误，一并入册）

### B-005 字库 bpp 节省量算错：130KB → 99KB

**错在哪**：我说 `lv_font_gb2312_16` 从 `--bpp 2` 改 `1` 能省约 130KB。实际只省 **99KB**。

**原因**：bpp 只影响 `glyph_bitmap`（198,435 B），而 `glyph_dsc`（61,936 B）与 `unicode_list`（7,516 B）**不受 bpp 影响**。我把"总体积砍半"当成了"整个模块砍半"。

**教训**：算节省量时，**先分清哪些部分跟着变、哪些不动**。

### B-006 "Sector 11 越界 → 凭据必然失效"推论被推翻

**错在哪**：我从"512KB 器件上 0x080E0000 不存在"这一步，直接跳到"凭据必然存不了"。前半有硬件直读支撑，**后半没有任何证据**。真机自动连接成功直接推翻了它。

**教训**：**推论走一步是推理，走两步就是臆测**。超出证据的部分必须标注为假设并设计实验，不能写成结论。

### B-007 `.trae/skills` 与代码漂移 3 处

| Skill 原文 | 代码实际 |
|---|---|
| ESP8266 在 USART3(PB10/PB11)、跳线 2/3 行 | **USART2(PA2/PA3)** 杜邦线；USART3 已给 RS485 |
| `configTOTAL_HEAP_SIZE` 须提到 49152 | 实际 **20480**（且与另一 skill 自相矛盾） |
| 阻塞 `HAL_UART_Transmit`、**不引入 printf 重定向** | 已改为 `UART_Printf` + DMA2_S7 + 互斥锁 + `fputc` 重定向 + `__use_no_semihosting` |

已全部订正（标注「YYYY-MM-DD 巡检订正」格式）。另订正 Flash 存凭据条目（sector 11 部分降级为存疑）。

**教训**：skill 是踩坑沉淀，但**会随代码漂移**；错的板级事实比没有更危险。建议每条加"最后核对日期"。

## B-008 中文字库吃掉 52% Flash

**现象**（数据来自本次 map）：

| 段 | 大小 |
|---|---|
| `lv_font_gb2312_16` glyph_bitmap | 198,435 B |
| 同字体 glyph_dsc | 61,936 B |
| unicode_list_1 + 3 | 7,516 B |
| **字库合计** | **≈ 268,000 B（262 KB）** |
| 其余全部代码 + RO | ≈ 232,000 B（227 KB） |

**而它只在 2 处被使用**：`GuiTask.c:534`（WiFi 热点列表）、`GuiTask.c:774`（密码弹层）。

**后果**：
- 内部 Flash 仅剩约 **23.8KB**，且**无完整空闲扇区**（程序占用贯穿 sector 0~7）
- SDIO/TF 卡驱动、LittleFS、MQTT 都塞不进去

**选项**：`--bpp 2 → 1`（省约 99KB）+ 适度裁剪字符集。**待用户决策**。
