**开工前请先读草案第 0 节，有一条会让 M1 直接失败的问题：**

> 🚩 厂商 `readID()` 用的是 **`0x90`**（返回 `0xEF17`），**不是 `0x9F`**。
> 你要的 **JEDEC ID `0xEF4018` 必须用 `0x9F` 读 3 字节**（EF/40/18）。
> 出处：`bsp_W25Q128.c:159` `sendByte(0x90);`，其宏 `W25Q128 = 0XEF17`（`c:24`）可印证。
> **照抄厂商 readID，永远读不到 0xEF4018。**

另两条：厂商 `WaitReady()` **无超时**（`c:95` 空 while）会死循环咬狗；厂商开 42MHz，建议 M1 降到 10.5MHz。

其余五节均在草案中（SPI 参数 / 命令序列表 / 时序表 / 心跳策略 / uvprojx 质检 ✅ 通过）。

三点需你注意：

1. **时序表只有 1 个数字有本地出处**（4KB 擦除 >150ms，`c:102` 注释）。本地无 W25Q128 数据手册（网盘只有 ST 参考手册），其余我标了"估算"。建议用 BUSY 轮询时顺手打印实测耗时回填，比抄手册更贴合这颗料

## 【驻场】黑屏事件分段定位（第一探针已上板，commit `84f7fcc`，推送待网络恢复）

**现场**（用户 22:28 串口记录）：boot 横幅 → reset cause → [WIFI] queues → free heap → flash size → magic 打印，**随后静默**。即挂死在 `W25Q128_Init()` 内部、第一条 [W25Q] 打印之前；调度器从未启动 → LCD 不初始化 → 黑屏。复位无效 = 确定性挂死。

**候选枚举**（挂死区内）：GPIO 配置（无循环，排除）、HAL_SPI_Init（纯寄存器写，排除）、`HAL_Delay(300)`（**靠 TIM4→HAL tick 计数等待，且是全工程第一次在调度器启动前调 HAL_Delay**——boot 诊断打印全是纯寄存器读，从没验证过 boot 阶段 tick 走不走）、SpiByte（等的是硬件标志位，flag 由外设自举， tick 冻结也顶多跳过超时检查，排除）。→ 头号嫌疑：**boot 阶段 HAL tick 不走导致 HAL_Delay 死等**。

**本探针三件套**：
1. `HAL_Delay(300)` → `W25Q_DelayMsBoot()`（DWT 周期计数忙等，TRCENA 一开就自由计数，不依赖 tick/中断/RTOS）——探针式修复：板子若起来，根因即实锤
2. Init 逐步留痕：`gpio ok` / `spi ok` / `delay ok`
3. 四个 Fault Handler（HardFault/MemManage/BusFault/UsageFault）进 handler 先轮询直发 `[FATAL]` 标记——区分"挂死"与"崩溃"，两种都是黑屏无日志，此前无法区分（这是本次排查的第一个盲区，顺手补掉）

**判定树**（下次烧录的串口日志怎么读）：
- 三行 ok + M1 PASS → 根因 = boot 期 HAL tick 不可靠（当时全工程无第二处依赖，影响面仅本函数）
- 停在 `spi ok` 无 `delay ok` → DWT 也走不动（极不可能），换纯 NOP 循环延时再探
- 出现 `[FATAL] xxx!` → 是崩溃不是挂死，按 Fault 类型查对应访问
- 三行 ok 但 JEDEC 全 1/全 0 → 回到原计划查线方向
