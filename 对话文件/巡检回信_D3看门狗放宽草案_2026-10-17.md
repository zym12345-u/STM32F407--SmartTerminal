## 一、D3 修复草案（核心交付，代码净增约 16 行）

### 1.1 先纠正一个前提：为什么只能是"提前放宽 RLR"，不能是"擦除期间周期喂狗"

`bsp_WifiStore.c:74` 的 `HAL_FLASHEx_Erase` 阻塞执行期间，**CPU 从 Flash 取指会停顿**（F407 单 bank，擦除时 Flash 不可读）。也就是说擦除进行中**代码根本跑不动**，任何"擦一会儿喂一次狗"的写法都执行不到。

所以唯一可行路径就是：**擦除开始之前**把窗口放宽，擦完再收回。你定的方向是对的。

> 需真机确认一条：本芯片擦除期间是否真的完全停取指（部分 F4 在 erase 时对指令取指的行为与总线等待状态有关）。若实测发现擦除期间代码仍能跑，则"分块喂狗"也可作为备选，但放宽 RLR 无论如何都成立，建议先按本草案实施。

### 1.2 参数取值与依据

现配置（`bsp_IWDG.c:13-16`）：`PR=256, RLR=125` → `T = 256×125/32000 ≈ 1.0s`

放宽目标：覆盖 **128KB 扇区擦除 max 2s**（你引的数据手册值）+ 编程 + 回读校验，并留 ≥2 倍余量。

```
IWDG_RELOAD_LONG = 750  →  T = 256×750/32000 ≈ 6.0s   (LSI=32kHz 标称)
```

| LSI 实际频率 | 实际窗口 | 是否覆盖 2s 擦除 |
|---|---|---|
| 32 kHz（标称） | 6.0 s | ✅ 3 倍余量 |
| 47 kHz（偏快，最不利） | 4.1 s | ✅ 2 倍余量 |

**代价**：放宽期间若真发生死锁，最长 6s 才复位（原 1s）。有界且可接受。

> ⚠️ 我未能从网盘资料中核到 F407 LSI 的 min/max 具体档位（该文件夹只有参考手册，无数据手册）。**请按数据手册核一次 LSI 频率范围**；若上限显著高于 47kHz，把 `IWDG_RELOAD_LONG` 相应上调即可，不影响结构。

### 1.3 代码

**`bsp_IWDG.h` 新增（3 行）**

```c
#define IWDG_RELOAD_LONG    750U            /* 256*750/32000 ≈ 6.0s,覆盖 128KB 擦除 max 2s */
void IWDG_SetTimeoutLong(void);             /* 长耗时操作前调用:放宽窗口 */
void IWDG_SetTimeoutNormal(void);           /* 操作结束后调用:恢复 1s */
```

**`bsp_IWDG.c` 新增（11 行）**

```c
static void IWDG_WriteReload(uint16_t reload)
{
    uint32_t guard = 100000U;                       /* 兜底:正常仅需数个 LSI 周期 */
    IWDG->KR = 0x5555U;                             /* 解锁 PR/RLR */
    while ((IWDG->SR != 0U) && (guard-- != 0U)) { } /* 等 PVU/RVU 清零 */
    IWDG->RLR = reload;
    IWDG->KR  = 0xAAAAU;                            /* 立即喂狗:从新值重新计数 */
}
void IWDG_SetTimeoutLong(void)   { IWDG_WriteReload(IWDG_RELOAD_LONG); }
void IWDG_SetTimeoutNormal(void) { IWDG_WriteReload(IWDG_RELOAD); }
```

**`bsp_WifiStore.c` 调用点（2 行 + 1 个 include）**

```c
#include "bsp_IWDG.h"                 /* 新增 */

/* WifiStore_Save() 内: */
    IWDG_SetTimeoutLong();            /* 插在 HAL_FLASH_Unlock() 之前 (现 67 行) */
    HAL_FLASH_Unlock();
    ...
    HAL_FLASH_Lock();
    IWDG_SetTimeoutNormal();          /* 插在 HAL_FLASH_Lock() 之后 (现 91 行) */
```

**恢复点选在 `HAL_FLASH_Lock()` 之后的理由**：该函数之后三条 `return`（95/101/103 行）**共用一个出口前缀**，插一处即可覆盖全部路径，不会出现"某条分支忘了恢复、窗口永久停在 6s"的漏洞。

### 1.4 失败回退与边界

- `guard` 兜底：`SR` 异常不清零时不会死循环，最坏是 RLR 没写成功 → 窗口仍 1s → 咬狗复位（退化为现状，不恶化）
- 放宽期间 MonitorTask 的 500ms 轮询与 3s 心跳判定不受影响，逻辑无需改
- 若放宽后仍咬狗 → 说明耗时超出 6s，应先取 `HAL_FLASHEx_Erase` 实测耗时再定，不要盲目继续加大

### 1.5 更彻底的修法（本轮不做，登记 V1.2）

放宽 RLR 只解决"误复位"，**不解决"擦完没写就复位 → 凭证丢失"**。根治要双扇区 ping-pong（先写备份扇区、再擦主扇区）或加事务标记。代码量远超 30 行，登记 V1.2。

**本轮草案可直接落地，不需等实测咬狗**——它把 1s 窗口换成 6s，对未触发的场景是纯增益、零风险。
